## Core architecture
- Prompt generated by API server (`/api/spark/today`) via OpenAI; in-memory cached per ET date.
- `useDailySpark` hook manages prompt state, answered state, streaks, memory lane.
- `useSparkCommunity` hook drives the community feed below the card.
- Firestore composite index required: `posts(sparkPrompt ASC, createdAt DESC)`.

## Eastern Time reset (America/New_York)
- **Both** `todayKey()` in the API server and `todayKeyET()` in `useDailySpark.ts` use `Intl.DateTimeFormat('en-CA', { timeZone: 'America/New_York' })` — returns YYYY-MM-DD in ET.
- `useDailySpark` tracks `today` as **reactive state** so a midnight rollover re-renders the hook.
- A `setTimeout` watcher (`getMsUntilETMidnight() + 250ms`) auto-fires at ET midnight, resets `hasAnsweredToday`, evicts the old prompt from localStorage, and reschedules for the next midnight.
- `firestore.ts` has `getETDayStart()` (tries UTC-4/UTC-5, picks whichever lands on ET hour 0). Used in `subscribeCommunitySparkPosts` and `checkTodaySparkAnswer` so yesterday's posts never surface after midnight ET.

## Performance / caching
- `useDailySpark`: localStorage caches today's prompt (`noelaven_spark_YYYY-MM-DD`). If cached, `loading` starts false — the card renders immediately.
- `useSparkCommunity`: sessionStorage caches the first PAGE_SIZE (20) responses keyed by `noelaven_community_<ET-date>_<prompt>`. On re-open the hook initialises from cache → `loading` is false → no skeleton shown.
- `subscribeCommunitySparkPosts`: initial limit is 20 (was 50). Caller calls `loadMore()` to bump pageSize by 20, which resubscribes with a larger limit (Firestore sends incremental diff).

## Skeleton cards
- Spinner in `CommunityReveal` replaced with three `<SparkSkeletonCard>` components (staggered by 80ms via `animationDelay`). Only shown when `loading` is true AND there is no cached data.

## Pagination
- `useSparkCommunity` returns `{ posts, loading, hasMore, loadMore }`.
- `hasMore` is true when `incoming.length >= pageSize`.
- "Load more responses ↓" button in `CommunityReveal` calls `loadMore()`.

## localStorage keys (useDailySpark)
- `noelaven_spark_<YYYY-MM-DD>` — today's prompt text
- `noelaven_spark_done_<YYYY-MM-DD>` — postId of user's response (presence = answered)
- `noelaven_spark_streak` — JSON `{ count, lastDate }` where dates are ET YYYY-MM-DD

## Why ET and not UTC
- All users must see the same daily question simultaneously. UTC would mean US West Coast users get a new question at 7pm or 8pm local time. ET midnight is the conventional reset for US-centric apps and keeps the window consistent for all users.
